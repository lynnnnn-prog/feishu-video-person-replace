# 配置与上线

## 四种凭证

所有凭证在 n8n 的 Credentials 中创建。JSON 只保留认证方式，不带原凭证 ID 或名称。

| 凭证 | 设置 | 绑定节点 |
| --- | --- | --- |
| 飞书入口 Header Auth | Name=`X-Webhook-Key`，Value=独立随机长密钥 | Feishu Generate Button1 |
| 飞书应用 Custom Auth | 按下面 JSON 配置 | Get Feishu Tenant Token1、Recovery - Get Token |
| Worker Header Auth | Name=`X-Worker-Key`，Value=Worker 的 `WORKER_API_KEY` | Submit Python Video Job1、Get Video Job Status1、Download Result Video1 |
| Google Drive OAuth2 | 用自己的 Google 账号授权 | Upload Result to Google Drive1 |

飞书应用 Custom Auth 的 JSON（仅填进 n8n 凭证管理，不放进工作流 Code 节点）：

```json
{
  "body": {
    "app_id": "YOUR_APP_ID",
    "app_secret": "YOUR_APP_SECRET"
  }
}
```

令牌请求节点通过 Custom Auth 将以上字段注入请求体。认证类型依据 [n8n Custom Auth 源码](https://github.com/n8n-io/n8n/blob/master/packages/nodes-base/credentials/HttpCustomAuth.credentials.ts)；入口 Header Auth 依据 [n8n Webhook 定义](https://github.com/n8n-io/n8n/blob/master/packages/nodes-base/nodes/Webhook/description.ts)。

## 导入工作流

1. 在 n8n 中作为**新工作流**导入 `workflows/aws.json` 或 `workflows/local.json`。
2. 在 `CONFIG1` 填写知识库节点 token、表格 ID、Worker HTTPS 根地址、Drive 文件夹 ID。配置不含 App Secret。
3. 按表格绑定各节点凭证。失败回写使用的 Recovery 节点也要绑定飞书凭证。
4. 确认新节点没有报“未知节点/版本不支持”，HTTP Request 支持错误输出，Code、IF、Wait 节点均可加载。模板沿用导出文件中的节点版本；目标实例是否兼容尚未实机验证。
5. 设置飞书按钮的 URL 和 `X-Webhook-Key`，先用测试记录试跑。
6. 测试完成后启用新工作流，再切换正式按钮入口。保留原工作流作为回退，不要同时用同一按钮触发两套。

建议同时保留独立 AWS 和本地模板：二者共享流程思路，但现有 Worker 接口不同。本地只允许 3–9 秒分段，AWS 旧配置是 10 秒并接受文案参数。

## 本地 Worker

需要 Python 3.10+，依赖版本在 `worker/requirements.txt`。若使用脚本，机器需要可用的 Python、网络及已授权的 ngrok。

1. 将 `worker/.env.example` 复制为同目录 `.env`，填写自己的 Gemini API Key 和 Worker Key。
2. 在独立目录启动新版 Worker，避免与当前占用 8080 端口的实例冲突。需要替换运行实例时，先完成旧任务，再停旧服务、启新服务。
3. macOS 可双击 `start_worker.command`，首次会安装依赖；其他系统可按下面命令启动。
4. 使用 ngrok 暴露到 HTTPS，再将根地址填入 n8n。

```sh
cd worker
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python worker.py
```

健康检查：`http://127.0.0.1:8080/health`。创建、查询和下载任务都要求 `X-Worker-Key`。`/jobs` 与 `/v1/jobs` 都保留。

`generate_audio: false` 已在本地请求模型中显式接收，并传入音轨合并流程。不要仅用新 JSON 搭配旧 Worker 期待声音处理已经改变；需要同时启动这份更新后的 Worker。

运行数据默认保存在 `worker/data/jobs/`，不会自动清理。目录中有源素材、生成素材、状态及可能包含私人信息的日志，已被 `.gitignore` 排除。`request.json` 不再保存飞书 access token。整个 `.env`、虚拟环境和旧任务均没有从原目录复制进项目。

## AWS 接口边界

当前 `aws.json` 继续请求：

- `POST /jobs`，返回 `job_id`。
- `GET /jobs/{job_id}`，返回 `status`，完成时可返回 `caption`、`tags`、`metadata_error`。
- `GET /v1/jobs/{job_id}/result`，返回视频文件。
- 请求体保留原接口的 `segment_seconds: 10`、`resolution: "720p"`、`generate_metadata: true`、`caption_language: "zh-CN"`，音频为 `generate_audio: false`。

云端需要核对：是否显式识别此布尔值；是否丢弃生成音轨并合并原视频音轨；是否保留分段时间线。只能根据现有 JSON 确认请求参数，不能据此断言服务器已实现这些行为。不要用本地 Worker 直接替换云端：本地不支持 10 秒和文案生成接口。

## 超时和失败处理

- 从 n8n 获得 `job_id` 时记下本次任务时间，每 20 秒查询；100 分钟后停止等待并回写失败。无需服务器返回 `created_at`。
- n8n 模板另设 120 分钟执行上限，给回写留余量。宿主实例或套餐若有更短上限，仍可能提前终止；应在实例中核对。
- 超时只停止 n8n 等待，**不会取消已提交的 Worker/模型任务，也不保证停止计费**。
- 查询、下载、飞书请求对节点级错误最多尝试 3 次。创建视频任务、上传 Drive 不自动重试，避免请求结果不明时重复生成或重复上传。
- HTTP 错误和飞书 HTTP 200 内的非零业务错误都进入失败处理。
- 失败处理重新获取飞书 Token，再尝试回写。若凭证失效、权限不够或飞书本身不可用，会让 n8n 明确显示失败；这种情况无法保证表格状态自动更新。
- 校验错误写回具体输入问题；一般运行错误仅写回执行 ID/已知任务 ID，不把原始密钥或完整请求内容放进表格。
- 手动取消、n8n 进程崩溃、宿主强制超时不能保证触发此工作流内部的回写分支。

## 上线试跑

依次验证：错误入口密钥被拒绝；正确密钥可取到测试记录；一个短视频可以生成并保留原声；成片可上传并回写；重复点击不会改成失败；故意填写错误 Worker 地址时能回写失败。

离线测试不访问你的 n8n、飞书、AWS、Drive 或模型账号，不能替代这些上线试跑。
