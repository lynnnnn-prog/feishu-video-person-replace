# 飞书多维表格模板

截图中的 10 个字段适合当前工作流，字段名称不需要重命名。下面是建议类型，截图不能确认的细节应在飞书字段设置中核对。

| 字段名 | 建议字段类型 | 配置与用途 |
| --- | --- | --- |
| 序号 | 自动编号，或数字 | 标识记录；原有序号可沿用 |
| 模板视频 | 附件 | 每条记录上传一个视频；代码只取第一个 |
| 人物参考图 | 附件 | 上传 1–3 张；第 1 张决定人物外观、服装等，后续作为辅助参考 |
| 人物性别 | 单选 | 固定选项“女”“男”；目前用于画面提示词，不改变原视频声音 |
| 生成视频 | 按钮 | 触发下方的 HTTP 自动化 |
| 状态 | 单选 | 预设“待生成”“生成中”“已完成”“失败”，新记录默认“待生成” |
| 输出视频 | 超链接 | n8n 写入 Google Drive 成片链接 |
| 错误信息 | 多行文本 | 写入输入错误、处理失败或异常执行提示 |
| post_content | 多行文本 | AWS Worker 返回的发布文案；本地方案不写入 |
| tags | 文本 | AWS 版写入 `#标签1 #标签2` 字符串；不要改成多选而不调整代码 |

左侧行号、勾选框是飞书界面元素，不是额外字段。

## 空白模板搭建

1. 新建多维表格，按上表创建字段及状态选项。
2. 本工作流沿用原来的知识库路径：将多维表格放在飞书知识库中，并配置其 `wiki_node_token` 和 `table_id`。它会通过知识库节点查询真正的 Bitable app token；普通独立表格链接的 app token 不能直接当作 wiki node token。
3. 为飞书应用授予相应的知识库节点读取、记录读取/写入、附件下载权限，并让应用获得该知识库及表格的访问权限。
4. 配置“生成视频”按钮触发自动化，添加“发送 HTTP 请求”操作。
5. 添加一条虚构测试记录，填入获准测试的视频及参考图；先完成测试，再保存为空白模板分享。

## 按钮自动化配置

- 方法：POST。
- URL：新工作流 Webhook 节点显示的生产 URL。测试时使用测试 URL，并在 n8n 启动监听。
- 请求头 `Content-Type`：`application/json`。
- 请求头 `X-Webhook-Key`：与 n8n Webhook 的 Header Auth 凭证一致。不要使用 Worker Key 替代入口密钥。
- 请求体：`{"record_id":"当前记录的记录ID"}`。其中值必须通过飞书变量选择器插入当前记录 ID，不能填写表里的“序号”，也不能保留文字占位符。

启用入口鉴权后，旧自动化如果没有增加请求头将被拒绝。这需要在飞书中配置一次；仓库文件无法替你修改现有飞书自动化。

## 使用说明

- 收到 HTTP 成功响应只表示请求已接收，是否生成完成以“状态”列为准。
- 当记录已经是“生成中”时，新请求会跳过，不覆盖原任务状态。
- 这个检查不是原子锁；几乎同时到达的两个请求仍可能并发提交。批量生产需要进一步在 Worker 增加幂等键或串行队列入口。
- “已完成”代表视频已上传。AWS 文案失败时可以保留已完成状态，并在错误信息中提示文案问题。
- 输出是 Drive 链接；是否有观看权限取决于 Drive 共享设置，本工作流不会自动设置为任何人可见。
- 本地版不会填写 `post_content` 与 `tags`，这两列可保持空白；不要把旧内容误认为本次生成。
